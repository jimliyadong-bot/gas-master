# 管理员端 · 采购商与库存管理（业务规则与数据模型）

> 适用范围：管理员端（原型 `m-stations.html` / `m-buyers.html`，状态逻辑 `assets/js/owner-store.js`）。
> 本文角色统称"管理员"（即原 PRD 的"站老板"、原型的"批发商"）。管理员端与消费者/加气员端（`c-*` / `s-*`）相互独立：加气员单站对应、散户扫码支付已定型，不在本文范围。

## 1. 角色与权限边界

| 对象 | 管理员权限 |
|---|---|
| 采购商档案 | 写（新增 / 编辑，含联系人、电话、预警阈值） |
| 采购批次 → 分批进气 | 写（登记批次、登记每次进气） |
| 库存调整（盘点） | 写（调增 / 调减，必填原因） |
| 出气 | 只读 —— 由"客户加气后扣减库存"自动产生，管理员只看数据、不录入 |
| 库存余量 / 预警 | 只读 |

采购商本人无任何登录端；库存预警通过短信通知到采购商预留电话（原型为模拟发送）。

## 2. 数据模型（对应 `owner-store.js`）

| 实体 | 关键字段 | 说明 |
|---|---|---|
| 采购商 buyer | id、name、contact、phone、**alerts** | `alerts:{CNG, LNG}` 为各气种预警阈值（m³/kg），可空 |
| 采购批次 batch | id(PO-)、buyerId、gas、qty、price、date、payment、invoice、paidAmount | 一批可分批进气 |
| 进气 receipt | id(IN-)、purchaseBatchId、buyerId、gas、qty、receivedAt | 累计进气 ≤ 批次采购量 |
| 出气 outflow | buyerId、gas、qty、status、occurredAt、batchId | 只读；batchId 指向进气记录 |
| 库存调整 adjustment | batchId(→receipt)、buyerId、gas、amount(±)、reason、createdAt | 挂到某条进气记录 |

## 3. 业务规则

- **先付后加**：库存余额恒 ≥ 0。已落地：进气不超批次余量（`remainingQty`）、调减不使进气批次为负。出气侧"余额不足拦截"在加气侧接入出气数据时实现，管理员端只展示。
- **库存派生**：进气批次余量 = 进气 − 出气(completed) − 调整；采购商某气种库存 = Σ 该采购商该气种各进气批次余量；CNG（m³）/ LNG（kg）严格分开。
- **出气只读**：管理员端只展示出气流水；原型阶段出气为演示数据，来源标注"客户加气扣减，待接入"。
- **付款状态不挂钩进气**：`payment`（待付款/部分付款/已付清）仅作财务跟踪，不限制可进气量。

## 4. 库存预警

- **阈值粒度**：按采购商 × 气种（单位不同必须分开）。
- **判定**（`alertsFor`）：该采购商该气种**已有进气**且当前余量 ≤ 阈值 → 预警。
- **展示**：库存页顶部"库存预警"卡片列出所有命中项（采购商、气种、余量、阈值），并显示命中数。
- **通知**：每项提供"短信提醒"按钮，模拟向采购商预留电话发送补货短信（无真实短信、无采购商端）。

## 5. 原型文件对应

- `assets/js/owner-store.js`：状态与校验；`alertsFor(data)` 派生预警列表。
- `m-buyers.html`：采购商（含预警阈值）、采购批次、分批进气、库存调整。
- `m-stations.html`：库存概览、进气/出气/调整流水、库存预警卡片与短信提醒。

## 6. 约定与待确认

- 预警通知仅面向管理员可见 + 短信通知采购商；不做采购商 App/门户。
- "未进气（余量 0）"不计入预警（需有进气历史才判断快用完）。
- 出气数据接入加气侧（核销扣减）的时机与字段映射，待加气侧定稿后再联调。
