# 加气站批量采购与销售记录系统 · 产品需求

> 版本：v1.0 需求重梳理｜日期：2026-11-13  
> 本文替代旧版“天然气分销平台 PRD v0.9”。旧版面向多客户、多站点的分销平台；当前目标是为一个加气站大客户管理批量采购资源、销售订单、库存和往来记录。

## 1. 产品定位与目标

### 1.1 产品定位

为**加气站的批量采购客户（采购商，即采购方）**提供一套轻量业务系统。采购方与采购商是同一业务主体，不是上下游两个角色；讨论中所称“供应商”也指该采购商，文档及界面统一使用“采购商”，不另设供应商主体。每个采购商对应多个加气站，每个站点有独立库存；每个采购批次只给指定站点的库存补货。站点管理员负责本站采购批次及到货补货的日常录入，由本人在确认弹窗中核对后提交入库，不需要他人审核；后台保留管理和调整能力，库存相关操作以查看、调整为主。采购商管理销售价格、优惠券、销售订单及资金记录；消费者扫描站点二维码下单并通过拉卡拉聚合支付；本站当班加气员核验订单并确认实际加气量；采购商和站点管理员分别查看各自范围内的采购、出气、余量、订单和资金记录。

本系统是采购方自己的经营与对账工具，不是给加气站提供的通用站务管理系统，也不做面向多个 B 端客户的平台化开放 API。

### 1.2 核心目标

- 记录向各加气站采购的数量、单价、金额、付款及票据信息。
- 通过扫码支付产生销售订单；按枪号和单价计算预计气量，作为订单参考。
- 支持消费者主动下单及加气员代下单两种方式；代下单须由司机确认后再支付。
- 支付完成后为订单生成动态核销码，由加气员扫码并确认实际加气量后完成订单。
- 加气员按班次操作，只有处于当班状态才能核销或代下单，并能交班。
- 每站独立库存：采购批次给指定站点补货，订单支付时预占本站库存，核销时按实际确认量扣减本站库存；取消或退款时按订单规则释放预占。不设置公共或跨站共享库存。
- 让采购方及时掌握销售、剩余库存、采购款和站点预警；让管理员查看本站采购、出气、余量、订单和收款/付款记录，并维护本站采购商及分批采购记录。
- 支持按今日、历史日期/时间范围、站点、采购商等条件查询。

### 1.3 非目标

- 不建设站点通用管理、枪机/设备管理、站点员工排班等站务系统。
- 不提供司机电子账户、充值、赠送金、余额支付或预付卡。
- 系统不设置车队这一业务实体，不做车队账户、车队专属库存或车队结算；车队人员与其他司机一样按散户下单、付款，从交易对应站点出气。
- 不建设面向外部企业/平台的 B 端开放 API、企业授信、企业门户。
- 不替代拉卡拉收银台；支付方式由拉卡拉提供微信、支付宝、云闪付等选项。
- 不将预计气量当作加气机实测数据或计量凭证。

## 2. 使用者与权限

| 使用者 | 主要能力 | 数据范围 |
|---|---|---|
| 采购商管理员（采购方管理员） | 后台查看、调整各站采购与库存，管理站点/价格基础资料、余量阈值、人员权限；不作为日常入库的必经审核人 | 全部采购方业务数据 |
| 采购方运营/营销 | 销售订单查询、优惠券创建/发放、经营统计 | 授权的采购方数据 |
| 采购方财务 | 采购付款登记、销售收款记录、对账、票据/开票跟进 | 财务及对账数据 |
| 消费者/司机 | 主动扫码下单；展示个人会员码接受加气员代下单；确认代下单、拉卡拉支付、展示动态核销码、查订单/优惠券 | 本人订单及优惠券 |
| 加气员 | 开始当班/交班；查看待加气订单；扫动态核销码确认订单；扫会员码代下单并等待司机确认 | 所属站点、当前班次内操作 |
| 站点管理员 | 在管理员端按采购批次录入本站到货补货，本人弹窗确认后提交入库；查看本站采购、出气、余量、订单、往来及票据提醒 | 仅本站数据；日常库存维护主入口参考 `design/prototypes/m-buyers.html`，档案等其他写权限另行明确 |

站点和枪号是业务基础资料，仅维护系统完成扫码、订单归属和对账所必需的信息；不延伸为完整站点运营管理。

## 3. 核心业务规则

### 3.1 采购与库存

1. 每个采购批次明确归属一个站点，用于给该站库存补货；由站点管理员在管理员端维护采购批次及本次到货补货，按站点、气种记录采购日期、数量、计量单位、采购单价/金额、付款状态与日期、付款方式、付款凭证、票据状态和备注。
2. **一站一独立库存**：一个采购商可有多个站点，但各站库存不合并、不共享，不存在采购商公共库存或车队库存。所有消费者均从交易对应站点出气，销售订单只能预占、扣减本站库存；批次是本站的补货和追溯记录，不是另外一个公共库存。
3. CNG 按 m³、LNG 按 kg 分开统计，不同气种不得直接相加；现有气种分项是在本站库存内分别记账，不改变一站一库存的归属边界。
4. **库存充足性只在下单时校验**：按订单预计气量检查本站对应气种可用库存，不足则不能下单。支付成功后仍按预计气量预占，核销时仍按加气员确认量记录实扣并释放剩余预占；但**实际加气／核销时不再以库存不足为由拦截**，本期不做加气中缺货处置流程。该简化不取消身份、本站归属、订单状态和重复核销保护；取消／核销前退款仍按订单规则释放预占。
5. 采购方可配置库存余量预警值；达到阈值时提醒采购方及时补充采购。系统可按采购批次余量提醒相关管理员关注票据/开票事项。
6. 本站可用库存 = 本站已生效补货量 + 净调整量 − 已核销实际气量 − 已预占量。系统记录所有采购、补货入库、预占、实扣、释放和人工调整流水，不允许静默改余额。
7. **到货上限采用方案 A（已确认）**：同一采购批次的累计到货量不得超过采购数量；超出部分另建采购批次，不允许仅告警后继续超量入库。这是采购入库边界，不改变销售核销时不因库存不足拦截的规则。

> **本轮已确认的操作流程：** H5 站点管理员在采购批次下录入本次到货／补货数据 → 弹出确认窗口 → 同一名操作人确认提交 → 保存成功后直接增加本站库存，不另等后台操作。取消确认不增加库存；不设第二人确认、采购商审核或后台审批环节。确认弹窗是录入人的防误操作步骤，不是审批流。
>
> 管理员端以 `design/prototypes/m-buyers.html` 为交互参考。后台也保留查看、调整采购和库存的能力，但不是日常入库的主入口或必经审核端；库存调整仍需记录原因和操作人。原型现有“采购批次 → 分次进气记录”结构作为流程参考，本轮不要求将两类记录合并。

### 3.2 扫码销售与支付

**主动下单**

1. 每站提供一个消费者支付二维码；扫码后识别站点，消费者输入/确认加气枪号并输入金额。
2. 系统按当前站点、气种、枪号的销售单价计算预计气量：`预计气量 = 订单金额 ÷ 销售单价`，保留两位小数并明确标注“预计，仅供参考”。
3. 消费者可使用采购方发行且满足条件的优惠券；折扣、叠加、适用范围、有效期等由采购方配置。
4. 消费者通过采购方拉卡拉商户支付；拉卡拉收银台提供微信、支付宝、云闪付等支付渠道。成功后订单进入待核销，生成该订单专属动态核销码。

**被动下单（加气员代下单）**

1. 消费者在个人页展示会员码；加气员处于当班状态时扫描会员码，录入枪号和金额并创建代下单订单。
2. 代下单订单先处于“待司机确认”，不得预占库存或记为已支付。
3. 司机确认订单内容后进入拉卡拉支付；支付成功后生成该订单专属动态核销码，等待加气员扫码核销。
4. 司机拒绝或订单超时，订单取消且不产生收款或库存扣减。

5. 不提供消费者充值、电子账户或余额支付。

### 3.3 订单与加气确认

订单状态：主动下单`待支付 → 待核销 → 已完成`；被动下单`待司机确认 → 待支付 → 待核销 → 已完成`；另有`已拒绝/已关闭`、`退款处理中`、`已退款`等状态。

- 支付成功后，司机端展示订单动态核销码；本站当班加气员在**加气前扫码核验**订单，核验通过后进行实际加气；加气结束后确认实际量并完成核销，记录完成时间和异常说明。
- 动态核销码只能关联唯一订单；过期、已核销、已取消或不属于本站的码必须拒绝并提示。
- **本期不处理实际量与付款不一致的资金差额**：加不下、少加或补加均线下处理，不新增线上自动补款、差额退款或按实际量重算应付流程。这不改变已有的实际确认量记录和本站库存扣减口径。
- **退款以完成核销为界**：完成核销前可以退款，不再另设“开始加气后不可退款”的业务门槛；其他退款场景本期不考虑，包括原方案的已完成订单后台退款。退款不需要审批，退款后的订单不能再核销。
- **扫码核验不等于完成核销**：加气前核验不把订单标为已完成，也不在此时按实际量扣减库存；实际量实扣随加气后的完成核销执行。本期不因此新增加气中状态或改变“完成核销前可退款”的规则。
- 加气员无法确认、重复确认、订单已取消等情况必须有明确提示并保留操作记录。
- 订单保留站点、枪号、气种、下单金额、优惠、实付、支付渠道、预计气量、实际确认气量、核销人和时间。

### 3.4 班次

- **每个站点同一时间只能有一名当班加气员进行订单核验、核销。** 加气员需先开始当班，才能查看/操作待办订单、扫码核销或代下单；其他人员不能同时核验、核销本站订单，非当班状态下只允许查看历史记录。
- 交班时生成班次摘要，包括当班时间、操作人、代下单数、核销数、气量和金额；未完成订单保留在站点待办列表，不随交班关闭。
- 开始当班、交班及班次内订单操作均记录操作人和时间。

### 3.5 采购商、往来款与票据

- 采购付款记录：采购批次、应付金额、已付金额、付款日期/方式、凭证和未付余额。
- 销售收款记录：订单实付、优惠、退款、拉卡拉渠道、交易状态及可取得的结算/手续费信息。
- 站点管理员通过本站采购批次维护补货和库存，本人确认后提交入库；后台以查看和调整为主，不承担每笔入库审批。采购商档案、付款和票据的具体编辑权限仍需与跨站资料边界一起明确，不由本次入库权限确认自动扩大。
- 订单、采购和付款/收款记录可按今日、历史日期/自定义时间范围、站点、气种、采购商筛选和导出，支持人工对账并保留差异说明。
- 按采购批次或约定周期展示采购票据/开票状态；采购批次接近用完时可提醒管理员关注开票。提醒对象、触发规则和谁负责开票待业务确认。

## 4. 功能范围

### 4.1 一期核心（原型重点）

| 模块 | 一期需求 |
|---|---|
| 采购方工作台 | 销售额、订单数、预计/实际出气量、按站/气种查看库存余量、库存预警和待加气订单 |
| 采购登记 | 站点管理员按本站采购批次录入补货；录入后本人弹窗确认，提交成功后入库，无第二人审核；后台主要查看、调整 |
| 库存台账 | 一站一独立库存，按站/气种展示补货批次、可用、预占、已消耗库存；余量阈值配置及提醒，无公共或共享库存模式 |
| 消费者扫码页 | 识别站点、确认枪号、输入金额、查看预计气量/单价/优惠、拉卡拉支付 |
| 订单与会员码 | 主动下单；展示个人会员码；确认加气员代下单；支付后展示动态核销码；查询订单历史 |
| 加气员工作台 | 开始当班/交班；查看待核销订单；扫码核销动态订单码；扫会员码代下单 |
| 优惠券 | 采购方创建券、设门槛/适用范围/有效期、定向发放及核销统计 |
| 管理员工作台 | 本站采购量、出气量、剩余量、订单及往来记录；以 `m-buyers.html` 为参考，通过采购批次录入到货补货并本人确认入库 |
| 对账记录 | 查看采购付款与拉卡拉销售收款记录，支持筛选和导出 |
| 查询 | 今日、历史日期/自定义时间范围，并按站点、采购商等条件筛选 |

### 4.2 暂不纳入一期

消费者电子账户及充值、授信/企业账户、外部 B 端开放 API、站点通用管理、复杂营销活动引擎、自动电子发票、全自动第三方财务对账等。

本轮另明确暂缓：

- 实际量与付款差额的线上处理；加不下或补加线下解决。
- 实际加气／核销时的库存不足拦截和现场缺货处理；库存充足性仅在下单时校验。
- 完成核销后的退款及其他特殊退款流程；本期只考虑核销前退款。
- 录错数据的专项更正流程；后续再在后台增加修改功能，不在本轮扩展。原有后台查看、库存调整及留痕能力不因此删除。

## 5. 原型页面与主要路径

1. **消费者主动下单**：站点二维码 → 确认枪号/气种 → 输入金额并查看预计气量 → 用券 → 拉卡拉支付 → 展示动态订单码。
2. **消费者被动下单**：司机展示会员码 → 加气员当班扫码并填枪号/金额 → 司机确认并支付 → 展示动态订单码。
3. **加气员核验、核销与交班**：开始当班 → 加气前扫动态订单码核验 → 实际加气 → 确认实际气量并完成核销 → 交班生成班次汇总。
4. **采购方经营**：查看工作台 → 登记采购批次及付款/票据 → 查看库存和余量预警 → 管理订单和优惠券 → 按今日/历史查询与导出。
5. **站点管理员补货与查账**：维护本站采购批次 → 录入本次到货／补货 → 本人弹窗确认并提交 → 本站库存增加；按今日/历史查看采购、出气、余量、订单及往来记录，处理提醒。后台以查看、调整为主，无第二人入库审核。

## 6. 关键数据

站点、枪号、气种、销售单价、采购商、采购批次、库存流水、订单、动态核销码、支付/退款记录、优惠券及核销、加气员确认记录、班次与交班汇总、采购付款、销售收款、票据状态、库存预警和操作日志。

## 7. 非功能与审计要求

- 订单支付、库存预占/释放/扣减保持一致，重复回调和重复核销不得重复扣减。
- 库存变动、采购付款登记、订单状态变更、优惠券发放和退款记录操作人、时间及原因。
- 动态核销码不得重放；代下单必须经司机确认后才能发起支付。
- 当班状态作为加气员操作权限门槛；班次交接保留未完成订单，不得漏单或重复结算。
- 拉卡拉支付结果以支付渠道回调/查单为准，前端跳转成功不能单独作为收款凭据。
- 消费者页面明确显示金额、优惠、预计气量和支付状态；不得将预计气量表述为实测量。
- 仅保存业务所需个人信息；采购方与管理员、加气员按职责隔离数据。

## 8. 业务确认与待确认事项
