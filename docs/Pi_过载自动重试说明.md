# Pi过载自动重试配置（2026-11-20）

用户要求在开始M2前，配置模型过载后自动重试，减少手工输入`retry`。本轮只调整本机客户端，不修改业务代码或数据库。

## 已设置

Pi版本1.5.2，使用内置agent级重试，不安装插件、不修改安装目录源码。

配置位置：`C:/Users/jim/.pi/agent/settings.json`。只修改其中的`retry`：

```json
{
  "enabled": true,
  "maxRetries": 8,
  "baseDelayMs": 10000,
  "maxAgentDelayMs": 60000
}
```

原配置为启用、最多3次、初始等待10秒；现在最多8次重试（加首次调用，共最多9次请求）。等待依次为10、20、40、60、60、60、60、60秒，累计等待最多370秒；这不包含各次请求耗时，不是整个任务的绝对时长限制。每个后续新的失败恢复周期有自己的重试预算。

- 精确报错`Codex error: Our servers are currently overloaded. Please try again later.`被当前内置错误分类识别为可重试；临时限流／部分5xx／断流等也沿用客户端内置分类。
- 登录认证错误、额度／计费耗尽不应一直重试；不修改分类规则，不自动切换模型或账号。
- 保留provider级重试默认0，避免两层重试叠加；只扩大agent级预算。
- 达到上限仍会停止并提示，不能保证服务永久不可用时无需人工处理。
- 默认`Esc`可取消。重试的是失败的模型轮次，不是重启项目或机械重跑此前工具命令；仍需保留业务幂等与提交结果核对。

## 生效与恢复

**当前会话需要在本次回复结束后输入一次`/reload`。** 新开的Pi进程会读取新设置。只验证了新SettingsManager能读到配置，不能把配置落盘说成现有会话的内存状态已经更新。

此设置为用户全局设置，对此电脑其他Pi项目也适用；项目`.pi/settings.json`可以覆盖。本项目目前没有这类覆盖。

仅原retry块备份在`C:/Users/jim/.pi/agent/retry-settings.before-20261120.json`，不包含其他配置或凭据。若回退，只把备份中的`retry`对象还原到主配置，**不要用整个备份文件覆盖主配置**；之后再`/reload`。


实际**7通过／0失败／0跳过**：

1. 使用安装版本SettingsManager读取本项目有效策略。
2. 核对8次实际退避计算及370秒累计等待。
3. 精确Codex过载文案、429和503识别。
4. 连续3次过载后第4次自动成功。
5. 持续过载在首次请求＋8次重试后停止。
6. 认证／额度错误不反复重试。
7. 等待中取消后不再请求。

测试使用安装版本的`retryDelayMs`、`retryAssistantCall`和错误分类函数；把模拟等待加速到1毫秒，不调用真实模型、不消耗模型额度。它不是当前交互会话的实际故障恢复演练。

另核对主配置JSON有效、除retry外其他配置的SHA-256指纹不变。没有读取`auth.json`或输出无关设置。相关依据为本机Pi的`docs/settings.md`、`docs/configuration.md`与内置重试源码。
