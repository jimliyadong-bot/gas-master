# 开发流水线：快速上手与SOP阅读指南

> 版本：v1.1｜日期：2026-11-21
>
> **你只需先读这份。** 你负责目标、关键决定和最终验收；AI负责读详细规则、拆任务、补工具、开发、检查和保存进度。
>
> **当前状态：已有SOP文档，尚未完成工作流Skill／快捷命令和自动编排器的安装验收。** 现在可以用自然语言按手动版操作，不能直接把`/flow-run`当成已可用命令。以后使用前先让AI核对实际安装情况。

## 1. 三份文档怎么读

| 文档 | 什么时候看 | 你先看哪里 |
|---|---|---|
| [手动版SOP](通用项目流水线开发SOP.md) | 现在就开始，按阶段给AI指令 | §1操作总表；需要时看§4—§7开发、§9换会话 |
| [自动版SOP](通用自动开发流水线SOP.md) | 希望批准后持续开发，不反复发“继续” | §1使用路线、§8授权、§17实现与启用验收 |
| [共用质量标准](开发质量门禁与正确性验证标准.md) | 判断交付是否达标，两种模式都要遵守 | §6放行、§10 UI、§11工具补齐、§12需求与交付核对 |

**不要三份从头背到尾。** 操作者按本页走，AI按当前阶段读取适用规则；详细SOP是遇到问题时的参考，不是让你手填一堆表格。

另有 [专业任务模板与交接约定](专业任务模板与交接约定.md)，由AI按需选用UI、实现、QA或诊断片段，并核对上下游产物。你不用额外管理角色或搬运截图，下面六步操作不变。

已有项目先核对进度，从当前未完成步骤继续；不机械重走已确认需求，也不重做已完成模块。

## 2. 日常操作：照这六步走

### 第一步：进入项目，告诉AI要做什么

在**目标项目目录**打开Pi，把所选SOP和共用质量标准通过`@文件路径`附上，或明确提供它们的实际路径。文档可以放在其他目录，但引用文档不会切换项目或继承那个项目的许可。

发送：

```text
请按我提供的SOP接入当前项目。我的目标是：【谁要做什么、解决什么问题】。
先读取项目规范、已有需求、计划和进度，只读核对现场与工作流能力。
先复述目标、说明当前阶段和关键问题，不直接编码，不重做已完成内容。
没有已安装并验收的自动编排器时，先用手动自然语言方式。
```

### 第二步：把需求说清楚

回答AI提出的关键问题，重点确认：**谁使用、主流程、本期做什么／不做什么、失败怎么办、怎样算完成。**

涉及UI时，让AI复用已有设计，或先给推荐方向；需要新设计时先确认代表页，再批量铺开，不必亲自决定每个字号和颜色。

理解无误后发送：

```text
确认需求【实际版本】中的【本期范围】。
未决定的事项继续保留，不自行补成默认规则。请据此拆分开发计划。
```

### 第三步：看计划，提出微调

发送：

```text
请按依赖拆分任务并审核计划，列出每步产物、验证方式、UI验收、必要工具和风险。
需要独立Review时列明角色与预算；没有相应许可先不要启动额外Agent。
给我一份简短计划及执行授权卡，明确需要我决定的事项，先不写业务实现。
```

你只需看：**有没有漏需求、顺序是否合理、先做什么、如何验证。** 不满意就说“先做A”“B拆小”“C本期不做”，AI负责更新依赖和记录。

### 第四步：批准明确范围

看过AI给出的计划和授权卡后发送；括号内容换成实际版本／编号，不空着照抄：

```text
确认需求【版本】、计划【版本】，批准【任务范围】及授权卡【编号】所列权限、角色与预算。
必要的免费本地技能／扩展／工具，按卡片策略自行安装、加载、调用并验证。
不要降低验收要求或扩大业务范围；新费用、提权、凭据、数据外传、提交和发布按各自许可处理。
```

同一已批准范围不需要每轮重新批准；发生需求、权限或关键验收条件变化时才重新确认。

### 第五步：开发、检查、修复

**手动方式现在可用：** 每轮发送下句，推进一个已获准任务；范围内的安装、测试和修复由AI完成，不需要你逐条指挥。

```text
请继续当前获准任务，完成实现、必要验证、审查和范围内修复，并保存进度与证据。
前端要实际查看页面／截图，满足共用UI标准，不能只报告构建通过。
只在真正需要新决定或无法恢复时找我；不要跳过失败项或擅自把缺项挪到下期。
```

**自动方式：** 仅在编排器实际安装并验收后使用。按实际入口启动批准批次，普通任务自动接续；你主要看状态、回答必要决策，不反复发送“继续”。

### 第六步：看结果，验收当前范围

要求AI给出：**完成清单、实际测试证据、适用UI截图与审查、未通过项、启动／使用说明。** 你按真实使用流程检查，再确认具体范围。

没测、失败或只是mock的部分不能写成真实通过。验收通过也不自动代表允许上线。

## 3. 想用快捷命令或自动版，怎么准备

- **只想少打字：** 按手动版§2.2让AI安装Skill／模板，再按§2.3演练。安装验收后才使用`/flow-init`、`/flow-next`、`/flow-save`；这仍是手动触发，不等于全自动。
- **想批准后持续自动开发：** 先按自动版§17实施并验收编排器；仅安装Skill不够。可以另行发送：

```text
请读取自动版SOP及共用质量标准，按自动版第17节提出分阶段落地计划和权限／预算供我确认。
批准后由你完成实现、必要安装、实际调用和恢复演练。
先在隔离小任务上验证可用，再接入正式开发；未验证的能力不要声称支持。
```

以上是以后执行的请求，不是阅读本页就会安装。正式启用后以实际提供的命令为准，拟定入口为`/flow-run`启动／恢复、`/flow-status`看状态、`/flow-pause`请求安全暂停。

## 4. 换会话、卡住或改需求时

**换会话前发：**

```text
请保存当前进度、批准范围、已验证结果、未完成项和精确下一步。
核对进行中操作与副作用，给我实际状态入口文件路径和新会话接续提示。
```

等AI确认保存结果后，在**同一项目目录**开新会话，发：

```text
请读取【上次给出的状态入口路径】及项目规范，核对现场后接续当前未完成任务。
保留原范围、预算和未通过项，不重新规划或重复执行结果未知的操作。
```

- **卡住：** 让AI先在许可内诊断、补工具、修复；确需你决定时，只回答它列出的最小问题。不要反复要求从头重跑。
- **改需求：** 先让AI分析影响，确认新版本后继续，不用“顺便加一个”绕过计划。
- **想暂停：** 明确要求暂停并保存；自动模式查看是否已安全暂停，不能把“暂停已请求”当作所有操作已停止。

## 5. 最后只记住这句话

**先说清需求 → 看计划并批准范围 → AI开发、检查、修复 → 看证据验收 → 保存后随时接续。**

手动／自动只改变谁触发下一步，不降低UI、正确性或权限要求；文档齐全也不等于软件已经安装、可用或没有缺陷。
